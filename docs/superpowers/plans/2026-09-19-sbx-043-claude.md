# SBX 0.43 Claude Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade all harnesses to the Docker Sandboxes 0.43.0 contract while making Claude provisioning use a global `sbxenv` and native read-only skills.

**Architecture:** Keep the shared launcher responsible for repository checks, deterministic names, direct workspace mounts, and non-Claude `sbx create/run` attachment. Move skills mounting to SBX's native `--skills=readonly` behavior and declare each custom image in its kit. Make Claude's kit self-contained by baking its plugin bootstrap into the custom image; its wrapper will apply the user-level environment with `sbx env create --name` and attach with `sbx run --name` so Claude arguments remain intact.

**Tech Stack:** Bash, YAML, jq, Docker Sandboxes 0.43.0, Docker custom templates, host-side shell tests.

**Spec:** `docs/superpowers/specs/2026-09-19-sbx-043-claude-design.md`

## Global Constraints

- Require Docker Sandboxes 0.43.0 or newer in launcher errors, documentation, and optional native-kit tests.
- Use native shared skills with read-only access; do not manually mount or symlink the host skills store from any launcher or bootstrap.
- Preserve Node `24.19.0`, Go `1.26.6`, OpenJDK `25`, Maven, and Gradle.
- Preserve deterministic `<prefix>-<repo-slug>-<8-hex-path-digest>` names, direct repository read/write mounts, and worktree guard exit code `3`.
- Keep credentials, MCP secrets, session state, generated images, caches, and machine-specific paths out of tracked files.
- Keep Caveman pinned to `v2.2.0`, revision `9aa63945a349bef17206540650db48c30fafbdf2`.
- Do not delete or recreate host sandboxes as part of this change; document that kit and skills changes require recreation.
- Do not commit changes unless explicitly requested.


  Change `setup.install[0].command` to `bash /usr/local/lib/claude-sbx/bootstrap.sh`, keep `user: "1000"`, and preserve all existing network permissions and agent instructions.

- [ ] **Step 3: Implement the Claude environment wrapper.**

  Keep the symlink-resolution and source-safe structure. Source `shared/launcher.sh` for the shared helper functions, then implement `claude_env_main` with this exact flow:

  ```bash
  command -v sbx >/dev/null 2>&1 || { ... require 0.43.0 ...; }
  command -v jq >/dev/null 2>&1 || { ... host jq message ...; }
  repo_root="$(repo_root_from_cwd)" || { ... return 2; }
  ensure_worktrees_ignored "$repo_root" || { ... return 3; }
  ensure_shared_skills "$(shared_skills_store)" || return
  name="$(sandbox_name_for_repo "$repo_root")"
  sbx env create --auto-approve --name "$name" || return
  if (($# > 0)); then
    sbx run --name "$name" -- "$@"
  else
    sbx run --name "$name" --
  fi
  ```

  Use the same user-facing repository and `.worktrees/` errors as the shared launcher. Do not call `sbx ls`, `sbx template ls`, `sbx create`, or pass a host skills-store mount from this wrapper. The root `bin/claude-sbx` delegate remains unchanged.
